# 风管厂的经验，不该只装在老师傅脑子里

## 我用 Obsidian 给技术部建了座经验库

上周新来的小李问我一个问题：共板法兰打孔，孔距到底是按新规则还是旧规则？

这个事儿，我 2026 年 7 月就整理过一份文档，连表格带图，写得明明白白。可是小李不知道，因为他刚来。而我当时想了半天才想起来那份文档放在哪个文件夹，最后还是在微信聊天记录里翻出来的。

三年前我自己踩过的坑，三年后新同事又踩一遍。

那一刻我就明白，技术部的经验一直存在，但存在的地方不对。存在人脑子里，存在聊天记录里，存在某个谁也不知道的 U 盘里。这些东西，人一走就没了。

## 一、知识不沉淀，等于没有

风管厂技术部，看着是"技术"，其实大部分知识长这样：

- 老师傅脑子里的经验："这个弯头展开，留 3 毫米就够了，多了咬口对不上"
- 微信聊天记录里的结论："上次不是说了吗，翻翻记录"
- 电脑里某个角落的文档："最终版""最终版2""打死也不改版"
- 图纸上的随手标注，画完就忘

这些东西有一个共同点：都在"人"身上，不在"系统"里。老师傅退休了，经验跟着走；聊天记录被清了，结论跟着没；文档改了三版，不知道哪版是对的。

我们厂之前也建过文件管理系统，把排版文件、图纸、订单都管起来了。但那是管"文件"的，不是管"知识"的。文件管住了，经验还是散的。

## 二、我试过的几种办法

最早我用 Word 写文档，一个文件夹一个主题，命名规范、编号规范，整得挺像回事。结果半年后没人看。为什么？因为找一篇笔记要打开文件夹、翻半天，还不如直接问老师傅。

后来我试过用 Excel 做"经验台账"，一行一条。倒是好查了，但写起来费劲，一条经验得拆成好几列，写完自己都不想看。

最后才轮到 Obsidian。

## 三、Obsidian 到底好在哪

说白了，Obsidian 就是一个本地 Markdown 笔记软件。但它有三个地方特别适合我们这种厂：

**第一，全文搜索。** 不管笔记建在哪一层，搜"共板打孔"，唰一下全出来。不用记文件放哪，记内容就行。技术部天天跟参数、规则、标准打交道，找东西靠搜不靠翻。

**第二，双链。** 一篇笔记可以链接到另一篇。比如"共板法兰打孔规则"可以链到"法兰角件清单""咬口预留量""GB50243 相关条款"。就像给知识织了一张网，从任何一条都能摸到相关的。

**第三，本地存储。** 笔记就是一个个 .md 文本文件，存在自己电脑里，也可以同步到公司服务器。不怕平台倒闭，不怕软件升级，文件永远是自己的。

现在我的知识库里攒了 200 多篇笔记，从管件排版参数到 CAD 快捷键，从 GB50243 解读到车间踩坑记录，啥都有。

## 四、踩过的坑，说给你听

听着挺美，但我一开始也走了弯路。

**第一个坑：把 Obsidian 当成第二个 Word。** 一开始我按文件夹分类，建了十几个文件夹，一篇笔记塞一个地方。结果笔记多了之后，我经常想不起来"这个东西到底归在哪个文件夹"。后来想通了，不按文件夹分，按标签分，再靠搜索和链接找。分类是给人看的，搜索是给结果看的，别指望分类能解决查找问题。

**第二个坑：光收藏不消化。** 有段时间我看到好文章、好资料就往里扔，笔记是多了，但都是别人的东西，不是我的。后来定了个规矩：每篇笔记必须有"我厂做法"这一段。资料是抄来的，但"我们厂怎么用"必须是自己写的。没有这一段的笔记，不算笔记。

**第三个坑：笔记写得太"规范"。** 我一开始按教科书风格写，标题分三级，段落工工整整。结果发现写得慢、改得勤、自己都不想看第二遍。后来改成大白话：问题是什么、原因是什么、厂里怎么干、当时踩了什么坑。像跟同事说话一样写，反而翻看率高了。

## 五、师傅们怎么用起来的

知识库建好了，最怕没人用。我们厂的做法是：不逼师傅们写，先让师傅们查。

小李那次问完我，我让他自己去知识库搜"共板打孔"。他搜出来之后，自己看了两遍，还顺便把链接里的"咬口预留量"也看了。从那以后，他问我的问题明显少了，问的都是知识库里没有的。

知识库这东西，写的人受益最大，但查的人才是让知识活起来的关键。现在技术部的新人培训，我都是让他们先翻一周知识库再上手。

## 六、小厂的知识，为什么总在"人"身上

暖通行业的小厂，普遍有个毛病：技术都靠"老带新"，师傅带徒弟。师傅教什么，徒弟会什么；师傅藏一手，徒弟就少一手。不是师傅心眼小，是很多厂根本没有沉淀知识的机制，经验只能靠嘴传。

这行的技术含量其实不低：管件展开、咬口预留、法兰孔距、加固间距，哪一样都有讲究。但这些讲究散在每个人的脑子里，厂里没有一个地方能查得到。等到老师傅一走，这些东西就跟着进棺材了。

中国制造讲究实在，可实在不能只靠人。老师傅的实在，得变成厂里的家底，才算留得住。我觉得未来小厂的差距，不在设备，在知识管理。同样一台咬口机，谁家的参数、经验、踩坑记录都在系统里，谁家的效率就高。

## 实操上注意这几条

有同行问我，Obsidian 入门到底怎么建。我建议别整太复杂，先跑起来，按下面这个模板写个 20 篇再说：

| 项目 | 内容 |
|------|------|
| 工具 | Obsidian 本地版，笔记存 .md 文件，可同步到公司服务器 |
| 目录 | 按车间生产环节分大类（排版、下料、成型、安装），别太细 |
| 标签 | 按主题打（参数/标准/踩坑/工具），一个笔记可多标签 |
| 笔记模板 | 问题 → 原因 → 标准依据 → 我厂做法 → 踩坑记录 |
| 硬规矩 | 每篇必须有"我厂做法"，光抄资料不算笔记 |
| 使用习惯 | 查 > 写，新人先查后问，老师傅定期补充 |
| 频率 | 一周哪怕只写一篇，一年也有 50 篇家底 |

刚开始别追求分类多严谨，也别追求格式多好看。先攒够 20 篇，你自然会知道该怎么调整。我的知识库就是先堆了三十多篇乱七八糟的，后来才慢慢理出现在的样子。

昨天小李又来找我，这次问的是防火阀检修口的事。我刚想开口，他自己接了一句："我先去知识库搜搜，搜不到再问您。"

行，这就算成了。小李现在问我的问题越来越少，不是他没问题了，是他学会自己找答案了。这比我多教他十个参数都值。
