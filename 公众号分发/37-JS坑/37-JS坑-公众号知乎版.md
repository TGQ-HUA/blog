## 从Delphi转WPS JS宏，踩过的坑比想象中的深

上个月车间日报那个宏突然罢工了。小周跑过来说报红字，我打开一看：

```
TypeError: Cannot read properties of undefined (reading 'Value2')
```

不知道哪个变量是undefined，也不知道哪一行。WPS JS的报错有时候就一句话，不给你堆栈。我写了十几年Delphi，`.Value`怎么可能变`undefined`？Delphi里变量没赋值，编译期就叫了，不会让你跑到运行时再猜。

查了一下午，原来是某个班组昨天没干活，没有产量记录。代码直接取空单元格的Value2，WPS返回的不是null，是undefined。后面所有操作全崩。

这件事让我意识到：从Delphi这种强类型环境跳到WPS JS宏里，有些思维惯性不改，迟早要栽。

---

### 一、undefined不是null不是空字符串，它什么都不是

Delphi里你声明 `var s: string;` 还没赋值，默认是空串，调用 `Length(s)` 返回0，不会崩。

WPS JS里，没赋值的变量是 `undefined`，不是null，不是空串，是一个单独的类型。而且WPS的对象方法经常返回undefined而不是null。

**我的应对**：每次从单元格读值，先判undefined：

```javascript
function 安全取值(cell) {
    let v = cell.Value2;
    return (v === undefined || v === null) ? "" : v;
}
```

说起来简单，踩这个坑之前我浪费了大半天。

---

### 二、WPS集合是1索引，JS数组是0索引

WPS里 `Worksheets(1)` 是第一个工作表，`Rows(1)` 是第一行。JS数组 `data[0]` 是第一个元素。

单独记哪套都不难。难的是一个函数里两套混着用：

```javascript
for (let i = 0; i < data.length; i++) {
    ws.Cells(i + 1, 1).Value2 = data[i]; // 别忘了+1
}
```

忘了+1？数据写到第0行——WPS不报错，第一行是空的，数据从第二行开始。查半天才反应过来。

---

### 三、Range.Value2返回值类型不固定

这是最阴的。

取**一个单元格**，返回标量值。取**一片区域**，返回二维数组。

你事先不知道区域有多大。用 `UsedRange` 取数据时，如果数据库某天只返回一条记录，宏又崩。

我现在加了个分支：先判断行数列数，一行一列按单格处理，多行多列按数组处理。

---

### 四、Application.Run传中文字符串

在WPS JS里调用另一个宏，用 `Application.Run("宏名", 参数1)`。如果参数是中文——某些WPS版本里它会变乱码。同一段宏，WPS 2021上正常，WPS 2019上中文变问号。

解决方案？不传字符串，传整数编号，让被调用的宏自己查字典。

---

### 延伸思考

我不是科班程序员。做风管的，技术部主管，管排版管下料管车间。学Delphi是十年前白天干活晚上自学，学WPS JS宏也是同一个模式。

市面上WPS JS的资料真的不多。大部头书没有，网上东一篇西一篇，很多是给VBA转JSA的人看的，对我这种Delphi转过来的不对口。我在Obsidian里建了个"WPS JS踩坑录"，到今天23条记录了，光undefined相关的就6条。

### 实操上注意这几条

| 问题 | Delphi做法 | WPS JS里的应对 |
|------|-----------|---------------|
| 取单元格值 | 直接取，类型固定 | 先判undefined，再转字符串 |
| 数组索引 | 统一0索引 | 分清JS数组还是WPS集合，注释标好 |
| 函数返回值 | 声明什么就是什么 | 不确定就加typeof检查 |
| 参数传递 | 编译期检查 | 能用数字就不用字符串 |
| 调试 | IDE断点+变量监视 | MsgBox+写日志到单元格 |

不高级，但在这个行当里，好用的比好看的重要一万倍。
