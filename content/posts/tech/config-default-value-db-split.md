## 一条报错，就一行

那天下午，跟单的姑娘在待办页点了「已同意」，屏幕上弹出一行红字：

> 发群失败：invalid webhook url

就一行，地址不合法。那段 key 是从企业微信后台复制过来的，按说不该出这种错。我原以为十分钟结案，最后查了两个多小时，还牵出一件大得多的事。

## 报错只说地址不合法，不说你把整条地址粘进来了

程序发群的时候，是把后台复制的那段 key 拼进一个固定地址：

```
https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=【key 填这儿】
```

配置的那次，复制时把整条 webhook 地址一起框了进去。程序再一拼，出来就是两层地址：

```
...send?key=https://qyapi.weixin.qq.com/...?key=74cf7267-...
```

企业微信当然不认，回一个 93000。

这事的教训不在「复制错了」，在于它为什么能藏住。key 那一栏在库里开的是 100 个字符，整条地址 89 个字符，塞得下，不报错也不截断，安安静静存了进去。等到发群那一刻才失败，提示还只说「url 不合法」，不会告诉你「你把整条地址粘进来了」。

修了两层。数据层把那条 key 还原成纯 key，36 个字符；代码层加了个小函数，粘纯 key 也行、粘整条地址也行，统一取出 key 那段，八种输入挨个试过。输入框提示也顺手改了：只填 key 那段就行，整条粘进来会自动取。

这个报错到此解决。麻烦的是，查 key 的时候我顺手对了一下数据。

## 屏幕上的东西，我这边全对不上

姑娘屏幕上的机器人叫「下单群」，我库里那个叫「下单通知群」；她那边流程配置 6 条，我这儿 0 条；待办 1 条，我这儿 0 条。

先怀疑缓存。清了一遍，还是对不上。

再怀疑程序版本。问了一下，服务器上跑的确实比开发机旧一版，但差距没那么大。

那就只剩一个解释：我们说的不是同一个库。

## 老库里，全对上了

我把服务器上那份配置文件翻出来看，程序连的是另一个库。切过去一查，屏幕上的东西全对上了，一条不差。

| 表 | 老库 | 新库 |
|----|------|------|
| 订单 | 19 条 | 19 条，逐行一样 |
| 人员 | 5 条 | 5 条，但账号密码是空的 |
| 待办 | 1 条 | 0 条 |
| 机器人 | 1 条（key 是错的） | 1 条（key 是对的） |
| 流程配置 | 6 条 | 0 条 |

服务器一直往老库写，我们开发测试一直往新库写，两边各写一半，已经这么过了半个月。

数据分家还在其次，麻烦的是「验证」这件事没法做了。我在开发机上测的每一条，验的都不是厂里在用的那份数据。我跟人说「没问题」，测的是另一个世界。

## 根因：新增的配置项，默认值指的是老库

程序里连库的配置项，代码里带了个默认值，默认值就是老库的名字。服务器上那份配置文件是早几年留下的，里面没有这一项，因为这一项是后来升级才加进去的。程序读配置读不到，就用默认值，不报错、不写日志，什么都不说。

省了一个配置项，代价是没人知道它到底连到哪儿去了。

处置按这个顺序来：以老库为准，整表同步到新库，同步前把两边的数据都导出备份，同步完逐表数数，数目全一致才算完；服务器上补上那一项配置，切到新库，重启服务。程序也改了，配置文件里没有库名这一项，直接起不来，不再自己拿默认值顶上。

## 顺带还发现一个雷

自动化测试的收尾，会清空「流程配置」那张表。它的清理逻辑是按「库里只有测试数据」写的，跑完把测试自己造的那几条删掉。可那张表现在装的是厂里的真实配置，测试一跑，配置就没了。

加了个备份恢复的小工具，跑测试前后各来一次。那天回归测试就是在「备份、测试、恢复」这个顺序下跑的，配置四张表原样还原。

## 实操上注意这几条

| 场景 | 规矩 |
|------|------|
| 程序新增配置项 | 默认值不许指向任何真实的库、真实的数据；缺项就拒绝启动 |
| 每次部署、换机器 | 部署清单上加一条：核对这台机器连的是哪个库 |
| 测试脚本会碰真实库 | 跑之前备份，跑完恢复，别指望清理脚本分得清哪些是它自己造的 |

## 最后

那行配置补上之后，服务器和新库对上了，跟单的姑娘再点「已同意」，群里能收到通知。老库我暂时没删，留着的，万一哪天翻出点别的东西，得有个地方对。
