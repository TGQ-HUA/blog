## 引子

上周机房换路由器，服务器 IP 从 192.168.2.100 变成了 192.168.2.101。很小一件事，网管十分钟搞定。

然后我这边炸了。

排版算量工具先报错——"连接失败"。打开代码找到 `服务器地址 := '192.168.2.100'`，改了，编译，发布，搞定。

第二天文件管理工具报同样的错——哦，这个工具里也写死了同样的地址。再改一次，编译，发布。

又过了一天，生产日报 WPS 宏也报错——宏脚本里面也硬编码了一条文件路径，指向的也是旧 IP。

一个 IP 地址，三个工具，改了三次还没改全。改第四次的时候我就在想：这活我不能干第五次了。

## 到底谁在"硬编码"

先说清楚啥叫硬编码。说白了就是把本应该灵活配置的值，直接写死在代码里。

比如这样：

```delphi
// 硬编码——IP地址直接写死在代码里
服务器地址 := '192.168.2.100';
API密钥 := 'liantai888';
数据目录 := 'D:\技术部-局域共享文件\生产文件\';
```

这段代码放一两个月没问题，但一旦环境变了——换服务器、换路径、换密钥——你就得翻代码挨个改。

更麻烦的是，不同工具的硬编码散落在不同文件里。Delphi 的写在 `.pas` 里，WPS 宏的写在 `.js` 里，Python 脚本的可能在 `.py` 头部。没有一个地方告诉你"还有哪些地方要改"。

## 从硬编码到 config.ini

解决思路不复杂：**把会变的参数抽出来，放到一个专门的配置文件里。**

在 Windows 平台，INI 文件够用了。TIniFile 是 Delphi 内置类，不需要装任何第三方库，语法也简单：

```delphi
uses System.IniFiles;

var
  配置: TIniFile;
begin
  配置 := TIniFile.Create(ExtractFilePath(Application.ExeName) + 'config.ini');
  try
    服务器地址 := 配置.ReadString('网络', '服务器地址', '192.168.2.100');
    API密钥    := 配置.ReadString('网络', 'API密钥', 'liantai888');
    数据目录    := 配置.ReadString('路径', '数据目录', 'D:\生产文件\');
  finally
    配置.Free;
  end;
end;
```

对应的 `config.ini` 文件：

```ini
[网络]
服务器地址 = 192.168.2.100
API密钥 = liantai888

[路径]
数据目录 = D:\技术部-局域共享文件\生产文件\

[版本]
版本号 = 2.1.0
```

所有工具读同一份 `config.ini`，换 IP 时改一个文件，重启软件就行。

## 一份配置文件救了哪个命

后来我把这个模式固定下来了。每个新的内部小工具，上来先把 `config.ini` 的结构设计好，再写代码。哪些值抽出来是有规律的：

| 类别 | 典型值 | 变化频率 |
|------|--------|---------|
| **服务器连接** | IP地址、端口号、数据库名 | 不常变，但一变就全崩 |
| **身份凭证** | API密钥、访问密码 | 定期轮换 |
| **文件路径** | 共享目录、备份目录、模板目录 | 按项目调整 |
| **运行参数** | 超时时间、重试次数、日志级别 | 调优时改 |
| **显示配置** | 窗口位置、列宽、最近打开文件 | 用户习惯 |

前两类是"不改就崩"的，后两类是"改了好用"的。不管是哪种，抽到配置文件里都比写死在代码里强。

## 实操上注意这几条

光说不练没用，说几个实际操作中容易忽略的点：

**1. 配置文件跟 exe 放同级目录或固定路径**

不要写死 `C:\config.ini`，也不要满世界找配置文件。约定俗成：`Application.ExeName` + `.ReplaceExt('.ini')`，或者 exe 同目录下的 `config.ini`。

**2. 提供缺省值**

`ReadString` 的第三个参数就是缺省值。配置项不存在时就拿缺省值，软件不会直接崩。新人拿到软件没有配置文件也能启动。

**3. 三个工具读同一份，还是各读各的**

看场景。生产日报排程用了三台不同机器，每台机器读同一份路径配置——那应该统一放在共享目录下。各工具之间有差异的参数（比如各自显示的窗口位置）则放各自的本地配置里。

**4. 配置文件不要做硬编码的翻版**

有些配置永远不需要改——比如 π 的值。不要把什么都往配置里塞。配置的边界是"这个东西未来可能变"。

## 一间工厂的小工具，也值得一份好配置

风管厂做的是钢板的活，但技术部用的这些小工具——排料的、算量的、下料的——也是小产品。硬编码是欠的技术债，迟早要还。早一天抽到配置文件里，改 IP 的时候就少熬一次夜。

后来服务器又换过一次 IP，我改了 `config.ini` 里一行，五分钟搞定三个工具全部生效。

老李问我："又改代码了？"

我说："没，改了个文本文件。"
