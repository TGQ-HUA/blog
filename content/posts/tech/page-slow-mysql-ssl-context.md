## 跟单的姑娘把手机递到我面前

「你点一下。」她在跟单页上点了个订单，屏幕上方开始转圈，转完才出内容。不是卡死，就是慢，慢到人烦。

这话我这两天听了几遍。排版页也一样，点开先愣一下，才慢慢铺出来。

第一反应是查询写得烂。这套系统是这几年一路自己攒出来的，页面里嵌套查询不少，我早知道有账要还。翻出来看，跟单页带的那几张表确实缺索引。

索引建了，测了一遍，快了一点，但圈还在转。

## 网络和服务器先排除

数据服务器在厂里，跟我这台机器在同一个千兆网段，ping 过去 1 毫秒以内。网络不像瓶颈。

我写了个小脚本，只做一件事：建一条数据库连接，连上立刻关掉，重复十五次，取中位数。

四毫秒多。

这就打架了。一条连接四毫秒，那张页面按四十条查询算，也就两百毫秒，剩下的一秒多上哪儿去了。

## 同一个库，两个脚本，差了一个参数

我的测试脚本连库时写的是 `pymysql.connect(**DB)`。程序里那个连接函数写的是 `pymysql.connect(**DB, cursorclass=DictCursor)`。

多一个游标类型而已，不该有区别。真要试的时候才发现，程序里其实还有第三样东西：我这套程序连的是新版本 pymysql，它建连接时默认要准备加密通信。

那就把这条路径单独掐一遍。每项跑十几遍取中位数：

| 怎么连 | 建一条连接要多久 |
|--------|----------------|
| 默认（准备加密通信） | 54.4 ms |
| 加 `ssl_disabled=True` | 4.2 ms |

五十毫秒。差十倍。

一台数据库，两个脚本，同一瞬间，同一条网线。差别只在这一个参数上。

## 那五十毫秒花在哪

继续拆。Python 里准备加密通信，第一步是先造一个 SSL 上下文，说白了就是一个装着证书、协议版本、验证规则的小盒子。程序每建一条新连接，都要现搓一个这样的盒子。

| 单独干这件事 | 耗时 |
|------------|------|
| 造一个 SSL 上下文 | 43.0 ms |
| 造上下文 + 把系统证书全部加载进来 | 93.3 ms |

四十三毫秒，基本就是那五十毫秒的主体。这台机器是 Windows，造上下文这一步要去翻系统的证书存储，翻一遍就是四十多毫秒。跑在局域网里的一次普通查询，本来五毫秒就能连上，硬是被这一步拖成五十。

再说个数字。我让脚本连着建四十条连接，模拟一张页面的开销：默认写法 2297 毫秒，关掉加密 499 毫秒。后者摊下来一条十二毫秒，比单独测的五毫秒贵，因为连着建的时候服务器那边每条都要给开线程；但跟两千三摆在一起，已经不是一个量级。人点的时候，就是"转圈"和"点开就有"的差别。

## 改成关掉，但留了个退路

连的是自己厂局域网里的数据服务器，中间不经过公网，加密这事在这儿没有实际收益。我把连接函数改成：

```python
return pymysql.connect(**DB, cursorclass=pymysql.cursors.DictCursor,
                       ssl_disabled=True)
```

改之前先确认了一件事：服务器本身是支持加密的（查 `have_ssl` 回的是 YES，MySQL 5.7.44）。也就是说之前不是服务器拒绝加密导致的等待，是客户端在准备这一套东西。这句话重要，如果服务器根本不支持，那走的就是另一条报错路径，关掉参数也治不了慢。

另外加了一层兜底。`ssl_disabled` 这个参数不是所有 pymysql 版本都有，老版本传进去会直接抛 TypeError。我把它包在 try 里，真抛了就退回原来那行，功能不能因为优化挂掉：

```python
try:
    return pymysql.connect(**DB, cursorclass=..., ssl_disabled=True)
except TypeError:
    return pymysql.connect(**DB, cursorclass=...)
```

## 别学我一半

这事有个前提，得说清楚：关掉加密只适合内网直连。哪天要把这套系统挪到公网、或者让外面的手机直接连库，这个参数必须去掉，或者老老实实配好证书。省下的一秒八，不值那个风险。

还有一层是我这次没动、但心里记着的：每一条查询都新开一个连接，本身就是浪费。四毫秒也是四毫秒，四十条就是一百六十毫秒。正经做法是连接复用（连接池），或者一次请求里只开一个连接、查询串着走。这次先把最贵的那五十毫秒砍掉，剩下的事排在后面。

还有一句得交代：我只有这一台 Windows 机器能测，Linux 上造上下文是不是也这么贵，我没测过，不敢替它下结论。要搬服务器，先自己掐一遍，别照抄我这句。

## 实操上注意这几条

| 情况 | 怎么办 |
|------|--------|
| 局域网直连自己的库，页面点开慢 | 先量单次建连接耗时，再看 SQL |
| 量出来一条连接几十毫秒 | 看是不是默认在准备加密通信 |
| 确定内网、不经过公网 | 加 `ssl_disabled=True`，并留 TypeError 兜底 |
| 要公网连库 | 别关，配好证书；或者干脆不让客户端直连 |
| 页面里查询很多 | 光省连接不够，接着做连接复用 |

## 收个尾

改完那天下午，跟单的姑娘又点了一下那张单子，页面直接出来了。她「咦」了一声，问我是不是换了台服务器。

没换。就是把一个没人注意的参数关掉了。

程序慢的时候，我总先想"是不是我 SQL 写得差"。这次不是。是程序每次出门干活之前，都要先穿一套根本用不上的盔甲，穿一次四十三毫秒。
